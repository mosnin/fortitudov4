# Shipping the site in three languages

`copy.md` says every language must carry the same plain meaning. This is how
that becomes true, and an honest account of how far it currently isn't.

## Where this actually stands

The site is **English-only**. Nine marketing pages, no translated route exists.

What already works, and is genuinely good:

- **`src/lib/i18n/markets.ts`** — country → language and country → currency, as
  two separate dimensions. A Spanish speaker in Chile reads the same es-419
  copy as one in Colombia but sees CLP rather than COP; someone in Berlin reads
  English and sees EUR. It also holds `decideLangRouting`, a complete routing
  decision covering geo, cookie, `?hl=`, and prefixed paths.
- **`src/lib/i18n/currency.ts`** — display-currency conversion. Live, and the
  only part of i18n a visitor currently benefits from.

What was written but never connected:

- `decideLangRouting` was not called from anywhere. `src/proxy.ts` ran Clerk and
  nothing else, so `?hl=` did nothing and neither cookie was ever written.
- `LangSwitcher` (in `local-price.tsx`) is exported and rendered nowhere. Its
  links point at `/es/pricing`, which does not exist.
- `dictionaries/pricing.ts` held 340 lines of the source template's copy for a
  different product — a real-estate CRM with trials, credits and per-seat
  brokerage pricing. One string of it was rendered.

So the routing engine is sound and the content layer was fiction. This plan
keeps the first and rebuilds the second.

## What gets translated, and what does not

**Translated** (7 pages): home, services, pricing, portfolio, about, contact,
faq — plus the shared chrome: header nav, footer, the closing CTA.

**Not translated**: `/privacy` and `/terms`. These are binding contract text.
A machine translation served as the operative agreement is a liability, not a
feature — a mistranslated limitation-of-liability clause is worse than no
translation at all. They stay English, and the translated pages link to them
with a short line saying the English version governs. Revisit only with a
lawyer, not with a better model.

This is a deliberate scope cut, not an oversight.

## Architecture

### Dictionaries

One file per page under `src/lib/i18n/dictionaries/`, following the pattern the
existing file already established and which is worth preserving:

```ts
const en = { … };                                  // canonical base
export type HomeDict = typeof en;                  // shape derived from en
const es: HomeDict = { … };                        // missing key = build error
const ru: HomeDict = { … };
export const HOME: Record<Lang, HomeDict> = { en, es, ru };
```

Two properties matter and both come free from that shape:

1. **English is the source of truth.** Adding a string to `en` breaks the build
   until every language carries it. Copy cannot silently ship untranslated.
2. **Numbers never live in prose.** Prices and counts interpolate via `{token}`
   through `fill()`, so currency localization applies everywhere at once and a
   price change cannot leave three languages disagreeing.

Dictionaries are plain data with no `'use client'`. That matters: this codebase
has already been bitten by importing a non-component value from a client module
into a Server Component, which turns it into a throwing stub — the bug shipped
as 16px headings on four pages. Keep dictionaries free of the client boundary.

### Routes

English stays unprefixed at its current paths. Translations live under a
`[lang]` segment:

```
src/app/(marketing)/pricing/page.tsx          → /pricing        (en)
src/app/(marketing)/[lang]/pricing/page.tsx   → /es/pricing, /ru/pricing
```

`generateStaticParams` returns `['es','ru']` only, and the page calls
`notFound()` for anything else, so `/de/pricing` is a 404 rather than a
half-rendered English page.

Both trees render the same content component with a different `lang` prop —
which is what `PricingContent` was already written to accept. There is one
implementation of every page, never a forked English and Spanish version that
drift apart.

### Proxy

`src/proxy.ts` composes language resolution with the existing Clerk handler. It
must never touch `/api/*`, `/dashboard`, `/admin`, or the auth routes —
redirecting an API call to `/es/api/...` would be a real outage.

**Language redirects stay switched off until the `[lang]` trees exist.**
`LOCALIZED_PATHS` names paths that have translations; pointing a redirect at a
route that hasn't shipped sends a geo-matched visitor into a 404, which is
strictly worse than serving them English. Cookie-setting and resolution run
regardless, so currency works before language does.

### Metadata

Each page emits `alternates.languages` for all three, and `<html lang>` carries
the right BCP-47 tag from `LANG_TAG`. Without those, Google treats the three
versions as duplicate content and picks one itself.

## The translation bar

From `copy.md`, and binding:

> A translation must carry the same plain meaning, not the same words — an
> idiom that lands in English and confuses in Spanish is a failed translation,
> even if it is accurate. Translate the outcome, not the sentence.

- **es** — neutral Latin-American Spanish (es-419), informal "tú". No vosotros,
  no Castilian idiom.
- **ru** — formal «вы».
- Both must pass the ten-year-old test **in that language**. Passing it in
  English and then translating faithfully is how you end up with a sentence
  that is correct, literal, and unreadable.

The banned-word list in `copy.md` has equivalents in both languages. Agency
noise translates depressingly well; do not let it.

## Order of work

1. English copy lands and is verified. Everything downstream derives from it,
   so translating before this is work thrown away.
2. Extract page copy into dictionaries, English only. Pages render identically —
   this step should be provably a no-op on the rendered DOM.
3. Translate to es and ru.
4. Add the `[lang]` trees, add the languages to `LOCALIZED_PATHS`, turn the
   proxy redirect on, render the switcher.

Steps 1–3 ship nothing user-visible. Step 4 is the one that goes live, and it
is deliberately last so that a partial translation can never be routed to.
